# دليل نشر Supabase لمشروع Agrima ERP (v11-cloud-r1)

هذا الدليل يشغّل الطبقة السحابية بالكامل على مشروعك المحدد:
**https://kcaertzyohhtcftlahcp.supabase.co**

تنفَّذ خطوات لوحة التحكم **مرة واحدة فقط**. بعد انتهائها لا تحتاج فتح
لوحة Supabase لإضافة أي مستخدم أو تأكيد بريد أو تعيين دور — كل ذلك
يتم من داخل Agrima نفسها عبر Edge Function آمنة.

---

## الخطوة 1 — تشغيل ملفات SQL (بالترتيب)

من لوحة المشروع: **SQL Editor → New query**، ثم الصق ونفّذ الملفات
الثلاثة بالترتيب، ملفًا بعد ملف (كل ملف آمن لإعادة التشغيل):

1. `sql/01_schema.sql`
   ينشئ: `profiles`, `user_roles`, `products`, `transactions`, `rolls`,
   `reels`, `permits`, `customers`, `audit_logs`, `sync_logs` + الفهارس
   وقيود التفرد + triggers (وقت التعديل التلقائي، وإنشاء ملف مستخدم جديد
   تلقائيًا مع أي حساب Auth).
2. `sql/02_rls_policies.sql`
   يفعّل Row Level Security على كل الجداول ويكتب السياسات الدقيقة
   (مدير/أمين مخزن) + يضيف جداول الأعمال لبث Realtime.
3. `sql/03_functions.sql`
   ينشئ دوال RPC: `app_record_login`, `app_stock_balances`,
   `app_recent_out_rows`, `app_next_permit_no` ويضبط صلاحيات التنفيذ.

**تحقق سريع بعد الخطوة:** Table Editor يجب أن يعرض الجداول العشرة.

## الخطوة 2 — نشر Edge Function `admin-create-user`

على جهازك (مرة واحدة):

```bash
# ثبّت Supabase CLI إن لم يكن مثبتًا
npm install -g supabase

# من مجلد المشروع (بعد رفع المستودع أو تنزيله)
supabase login          # يفتح المتصفح لربط حسابك
supabase functions deploy admin-create-user \
  --project-ref kcaertzyohhtcftlahcp
```

لا توجد أسرار يدوية مطلوبة: الدالة تستخدم `SUPABASE_URL` و
`SUPABASE_SERVICE_ROLE_KEY` المُحقنين **تلقائيًا** في بيئة الدوال،
ولا يظهر أي منهما أبدًا في الكود أو المستودع أو المتصفح.

### الأسرار (Secrets) المطلوبة يدويًا: لا شيء
| السر | من يديره | أين يظهر |
| --- | --- | --- |
| Publishable Key | متصل في `js/supabase.js` | عام بالتصميم — لا يمنح أي وصول بحد ذاته |
| Service Role Key | بيئة Supabase فقط | يُحقن تلقائيًا في Edge Function — غير موجود في أي ملف |
| أنت | لا تحتاج إضافة أي Secret يدويًا | — |

لو احتجت لاحقًا متغيرًا خاصًا: `supabase secrets set NAME=value` —
ولا تضعه في أي ملف يصل للمتصفح أبدًا.

## الخطوة 3 — إنشاء أول مدير نظام (بأمان)

هذه آخر مرة تحتاج فيها لوحة التحكم. الهدف: حساب مدير واحد مؤكد.

1. **Authentication → Users → Add user → Create new user**
   - البريد وكلمة مرور قوية (8+ أحرف).
   - فعّل **Auto Confirm User** (يؤكد البريد فورًا).
2. سيتولد له ملف في `profiles` بدور فارغ تلقائيًا (trigger) —
   لا يمكنه الدخول للتطبيق بعد.
3. من **SQL Editor** نفّذ سطرًا واحدًا (استبدل البريد):

```sql
update public.profiles set role = 'admin' where email = 'admin@yourdomain.com';
```

4. سجّل الدخول من التطبيق بهذا الحساب — أصبحت مدير النظام،
   وكل ما يلي يتم من شاشة **المستخدمون والصلاحيات** داخل Agrima:
   إضافة مستخدمين وتأكيد بريدهم تلقائيًا وتعيين أدوارهم وإيقافهم أو
   تفعيلهم وإعادة تعيين كلمات مرورهم — دون أي فتح للوحة مرة أخرى.

## ماذا يحدث بعد النشر؟ (اختبار قبول سريع)

| # | السيناريو | المتوقع |
| --- | --- | --- |
| 1 | دخول المدير | يفتح التطبيق بكل الأقسام |
| 2 | المستخدمون → + مستخدم جديد (أمين مخزن) | يُنشأ الحساب وتأكد بريده تلقائيًا وتظهر بيانات الدخول مرة واحدة |
| 3 | دخول الحساب الجديد | يعمل فورًا بلا بريد ولا لوحة |
| 4 | أمين المخزن | يرى الرصيد وأذون اليوم والأمس فقط، وينشئ إذنًا (مسودة)، لا يرى تقارير/مستخدمين/إعدادات |
| 5 | محاولة أمين المخزن استدعاء جدول مباشرة عبر API | تُرفض بـ RLS (صفوف فارغة أو خطأ) |
| 6 | اعتماد الإذن من المدير | يخصم من الرصيد ويزهر عند أمين المخزن خلال ثوانٍ (Realtime) |
| 7 | فصل الإنترنت عند المدير | يستمر العمل محليًا، وعند العودة تُزامن السجلات تلقائيًا دون تكرار |

## الأمان — ملخص الضمانات

- **الفرض الفعلي في قاعدة البيانات**: كل سياسة أعلاه تُطبق على مستوى
  Postgres، فلا يكفي تعديل JavaScript ولا إرسال طلبات مباشرة لتجاوزها.
- **منع ترقية الصلاحيات**: المستخدم لا يستطيع تغيير دوره أو حالته
  (سياسة profiles_update)، وإنشاء الحسابات يمر حصرًا عبر الدالة التي
  تتحقق من أن الطالب مدير نشط قبل استخدام أي صلاحية إدارية.
- **سجل التدقيق غير قابل للعبث**: `audit_logs` و`sync_logs` بلا أي
  سياسة UPDATE أو DELETE لأي مستخدم.
- **كلمات المرور**: تُخزن هاش داخل `auth.users` فقط — لا نص عادي في
  أي جدول، ولا تُعرض إلا مرة واحدة عند الإنشاء.
- **الجلسة**: تُخزن محليًا للعمل دون إنترنت، ويتحكم بها Supabase Auth
  (إبطال الحساب يسري فورًا عبر RLS).
