# Agrima ERP — إدارة المخزون والبكر وأذون الصرف وحجوزات العملاء

نظام ERP احترافي يعمل بالكامل داخل المتصفح (PWA بدون خادم وبدون خطوة بناء)، واجهة عربية RTL بطراز مؤسسي (كحلي/رمادي/أبيض)، مربوط بـ **Supabase** لتسجيل الدخول والصلاحيات والمزامنة، ويحافظ على العمل **دون إنترنت** عبر IndexedDB كما في النسخ السابقة — بنفس محرك الحسابات وبيانات المستخدم دون أي فقد.

> التطبيق المنشور: https://anamiir2-collab.github.io/Agrima

---

## ما الجديد في v10 (ERP + Supabase + صلاحيات)

1. **تصميم ERP جديد بالكامل:** قائمة جانبية مجمّعة (الرئيسية / العمليات / الإدخال / البيانات / الإدارة) بأيقونات SVG خطية، شريط علوي فيه حالة المزامنة + قائمة المستخدم، بطاقات أرقام بلمسات حالة، جداول موحدة (نفس تصميم الشاشة هو نفسه للطباعة)، بحث وتصفية وفرز، ألوان هادئة كحلي/رمادي/أبيض — بلا زخارف.
2. **نظام مستخدمين بصلاحيات حقيقية من قاعدة البيانات (RLS):**
   - **مدير النظام (admin):** كل الأقسام وكل العمليات دون استثناء — إضافة/تعديل/حذف/اعتماد، إدارة المستخدمين، الاستيراد والتصدير، النسخ الاحتياطي، سجل العمليات، الإعدادات والمزامنة.
   - **أمين المخزن (warehouse):** **عرض وطباعة فقط** — الرصيد الحالي (مع تفاصيل البكر والأوزان والمقاسات) + أذون **اليوم والأمس بتوقيت مصر Africa/Cairo** مع البحث داخلها وطباعتها. ممنوع عليه إضافة/تعديل/حذف/اعتماد/تقارير/عملاء/حجوزات/مستخدمين/إعدادات/استيراد/تصدير/نسخ احتياطي — **المنع مطبَّق بسياسات RLS في Supabase نفسها وليس مجرد إخفاء في الواجهة** (محاولة الاستعلام المباشر من REST أو أدوات المطور تُرفض من الخادم).
   - **قاعدة آخر يومين:** تُحسب من حقل تاريخ الإذن الفعلي بتوقيت القاهرة، وتتحرك تلقائيًا عند بداية يوم جديد — ولا يمكن تجاوزها بتغيير الرابط أو التاريخ في الفلاتر (الفلاتر مثبتة للقراءة على جهاز أمين المخزن، والسياسة مطبقة على الخادم).
3. **مصادقة Supabase Auth:** شاشة دخول كاملة، جلسة آمنة محفوظة محليًا تعمل دون إنترنت، خروج، استعادة الجلسة، حساب بلا دور أو موقوف = صفر وصول.
4. **مزامنة محلي أولًا (Local-first):** كل التعديلات تُحفظ فورًا في IndexedDB ثم تُزامن مع Supabase تلقائيًا (كل دقيقتين للمدير وعند عودة الإنترنت). قواعد صارمة:
   - معرف ثابت فريد `sid` لكل سجل — **لا تكرار نهائيًا**.
   - **لا يُكتب فوق سجل أحدث بسجل أقدم مطلقًا**؛ المحلي المعدّل وغير المرفوع يفوز ويُرفع، والسحابي الأحدث يُقبل، والتعارضات تُسجل.
   - **الحذف ينتقل بعظام قبر (tombstones)** فلا يعود السجل المحذوف من السحابة، وعمليات المسح الشامل تسجل عظام قبر قبل المسح.
   - أمين المخزن يستقبل فقط (رصيد تجميعي عبر دالة RLS آمنة + أسطر اليومين) ولا يرفع شيئًا.
   - كل جلسة مزامنة تُسجل في `sync_logs` مع الأخطاء.
5. **سجل عمليات (Audit Log):** تسجيل الدخول/الخروج، إضافة/تعديل/حذف/اعتماد أذون الصرف، تغييرات المخزون، إدارة المستخدمين والمزامنة — للمدير فقط، و**لا يوجد أي سياسة تعديل أو حذف له في قاعدة البيانات**.
6. **شاشة المستخدمين (للمدير):** إضافة مستخدم بدور محدد مع توليد كلمة مرور قوية تُعرض مرة واحدة، تفعيل/إيقاف فوري (يقطع الوصول عبر RLS)، تغيير الدور مع سجل تاريخي، إعادة تعيين كلمة المرور عبر البريد، آخر دخول، وسجل عمليات كل مستخدم. **لا توجد أي كلمة مرور أو مفتاح سري داخل ملفات المشروع** — المفتاح المستخدم في المتصفح Publishable Key فقط ولا يمنح أي وصول بحد ذاته.
7. **الحفاظ على كل وظائف v9 كما هي:** لوحة التحكم، الرصيد الحالي، تسجيل البكر، إدارة الرولات والبكر، سجل الإنتاج (عرض فقط — الإنتاج من تسجيل البكر)، أذون الصرف بمسودة/اعتماد، حجوزات العملاء (تتبع مستقل)، سجل حركات الصرف، العملاء، الأصناف، 9 تقارير A4، الاستيراد/التصدير، النسخ الاحتياطي/الاستعادة، والإعدادات. قسم المشتريات والموردين يبقى **مستبعدًا من الواجهة** (ملفه محفوظ دون تحميل كما في v9 الأخيرة).
8. **ترحيل قاعدة البيانات المحلية v3 → v4 إضافي بحت:** متاجر `tombstones` و`stockview` + فهرس `sid` — لا قراءة ولا إعادة كتابة ولا حذف لأي سجل قائم، وبياناتك القديمة تعمل كما هي فورًا حتى قبل إعداد Supabase.
9. **الاختبارات الآلية:** 37 اختبارًا قديمًا + 23 اختبارًا جديدًا (نافذة توقيت القاهرة، مصفوفة الصلاحيات، قواعد التعارض، عظام القبر، الترحيل الإضافي، تحويل الحقول) — `npm test` → **60/60 ناجح**. فحص متصفح حقيقي: تشغيل، دخول محلي دون إنترنت، حارس المسارات، الطباعة A4، الجوال 375px بلا فائض أفقي، إعادة تحميل أوفلاين من ذاكرة PWA — بلا أي أخطاء Console.

## التشغيل السريع (بدون Supabase)

التطبيق يعمل محليًا كما كان تمامًا قبل الربط — افتح `index.html` عبر أي خادم ثابت (أو انشره على GitHub Pages). عند أول تشغيل ستظهر شاشة الدخول؛ ستجد زر **«الدخول بوضع محلي»** فقط عندما يكون الجهاز غير متصل بالإنترنت. لتفعيل الحسابات والصلاحيات والمزامنة أكمل إعداد Supabase أدناه.

```bash
# فحص محلي
python3 -m http.server 8080
# ثم: http://localhost:8080

# الاختبارات
npm install && npm test
```

## إعداد Supabase (خطوات يدوية إلزامية — مرة واحدة)

> هذه الخطوات تحتاج لوحة المشروع: https://supabase.com/dashboard/project/mhobdjqbpsjmbvjditti
> بيانات الاتصال موجودة في `js/supabase.js` (URL + Publishable Key) ولا تحتاج تغييرًا.

### 1) إنشاء الجداول
SQL Editor → الصق **`sql/schema.sql`** كاملًا → Run.
الملف آمن للتكرار (يُنشئ فقط ما لا يوجد — لن يمس أي جدول أو بيانات قائمة).

### 2) تفعيل سياسات الأمان RLS
SQL Editor → الصق **`sql/rls-policies.sql`** كاملًا → Run.
هذا يفعّل RLS على كل الجداول ويطبق:
- مدير النظام: كل شيء. أمين المخزن: قراءة الرولات والبكر + أذون `date >= (تاريخ القاهرة − 1)` فقط + الرصيد عبر `app_stock_balances()` التجميعية.
- لا أي سياسة كتابة لأمين المخزن — أي محاولة INSERT/UPDATE/DELETE من حسابه تُرفض من الخادم (وليس من الواجهة).
- الحساب بدون دور أو الموقوف: صفر وصول. لا يمكن لأي مستخدم تعديل دوره بنفسه.
- سجل العمليات: إلحاق فقط — لا سياسة تعديل أو حذف لأحد.

### 3) إنشاء أول حساب مدير
SQL Editor → الصق **`sql/initial-admin-setup.sql`** → Run (ينشئ الدالة فقط)، ثم نفّذ:

```sql
select public.app_create_initial_admin(
  'بريد-المدير@الشركة.com',
  'كلمة-مرور-قوية-كتبها-الآن'
);
```

كلمة المرور تُدخل عند التشغيل نفسه ولا تُخزن إلا كهاش bcrypt — لا بيانات دخول ثابتة في المستودع. النتيجة `true` = جاهز.

### 4) إعدادات المصادقة في لوحة المشروع
- **Authentication → Providers → Email:** فعّل البريد/كلمة المرور.
- **Authentication → Providers → Email → «Confirm email»:** أوقفه (بدون تأكيد بريد) لكي تُنشأ حسابات الفريق من شاشة المدير مباشرة وتُرجع جلسة صحيحة. إن تركته مفعّلًا سيحتاج كل حساب جديد لفتح رابط تأكيد قبل الدخول.
- **إعادة تعيين كلمات المرور:** تعمل عبر بريد Supabase الافتراضي أو SMTP الذي تضيفه من Authentication → Emails.
- (اختياري) قلّل Rate limits حسب حجم الفريق.

### 5) إنشاء باقي الحسابات — من داخل التطبيق
سجّل الدخول بحساب المدير → **المستخدمون والصلاحيات** → «مستخدم جديد»: الاسم، البريد، الدور (مدير/أمين مخزن)، وزر توليد كلمة مرور قوية تُعرض **مرة واحدة** لنسخها وتسليمها للمستخدم. لا حاجة لـ SQL مرة أخرى.

## المزامنة والعمل دون إنترنت

- **المحلي أولًا:** أي عملية (حركة، إذن، بكر…) تُحفظ في IndexedDB فورًا كما في النسخ السابقة — بدون إنترنت يعمل كل شيء، وعند الدخول بوضع محلي (زر يظهر فقط عند انقطاع الاتصال) يعمل التطبيق على بيانات الجهاز بلا مزامنة.
- **المدير:** سحب ثم دفع تلقائي (كل دقيقتين وعند عودة الاتصال)، والمشاهدون يرون شريط حالة المزامنة في الشريط العلوي وزر «مزامنة الآن» في شاشة المزامنة.
- **منع التكرار:** كل سجل يحمل `sid` ثابتًا يُطابق عمود `sid` في Supabase (upsert على `sid`).
- **التعارض:** قاعدة «الأحدث يفوز» مع حماية المحلي المعدّل وغير المرفوع، وتسجيل كل قرار في `sync_logs` — لا كتابة فوق أحدث بأقدم ولا فقد بيانات محلية أصلية.
- **الحذف:** ينتقل بعظام قبر (تسجل قبل المسح في عمليات الاستبدال/إعادة الضبط أيضًا) — السجل المحذوف لا يعود من السحابة.
- **النطاق:** تُزامن المتاجر: products, transactions, rolls, reels, permits, customers, audit. الإعدادات المحلية (اسم الشركة، معامل الوزن) تبقى لكل جهاز.

## الطباعة

- جدول الشاشة هو نفسه جدول الطباعة (نفس الترتيب والأسماء والتنسيق) — الطباعة تخفي أدوات التحكم فقط.
- إذن الصرف A4: العدد | المقاس | الجرام | الصنف + إجمالي الجرامات + الإجماليات + التوقيعات، ويُطبع من اللقطة المحفوظة نفسها.
- التقارير التسع بترقيم صفحات حقيقي وتكرار الترويسة — كما في النسخ السابقة دون تغيير.

## النسخ الاحتياطي

كما في v9 (يغطي كل المتاجر مع فحص مخطط قبل الاستعادة وتنزيل تلقائي قبل الاستبدال)، ويشمل الآن متاجر v4 (`tombstones`, `stockview`). الاستعادة تسجل عظام قبر قبل استبدال نطاق الرصيد فلا تعود الصفوف المستبدلة من السحابة.

## الخصوصية والأمان

- **لا يوجد أي Service Role Key أو Secret Key في المستودع** — فحص آلي (`tests/test-erp.js`) يمنع تسربها.
- Publishable Key آمن للنشر لأنه بلا صلاحيات بحد ذاته؛ الحماية الفعلية: Supabase Auth + RLS.
- كلمات المرور: هاش bcrypt داخل `auth.users` فقط، وتوليد العرض مرة واحدة من شاشة المدير.
- سجل العمليات غير قابل للتعديل أو الحذف من أي حساب.
- جدول `auth.users` مباشرًا لا يمكن للمستخدمين قراءته؛ بيانات الحساب للعرض عبر `profiles` فقط.

## ما تم اختباره فعليًا وما يحتاج خطوتك اليدوية

**تم اختباره فعليًا:** 60/60 اختبار Node، تشغيل متصفح حقيقي (شاشة الدخول، الوضع المحلي دون إنترنت، حارس المسارات لأمين المخزن، أذون الصرف بالنافذة الثابتة، المستند A4، الجوال 375px، إعادة تحميل أوفلاين من PWA) — **بلا أي خطأ Console**.

**لم يُختبر من هذه البيئة (يتطلب لوحة Supabase لديك):** تنفيذ ملفات SQL الثلاثة، إنشاء أول مدير، تسجيل دخول سحابي فعلي، وتدفق المزامنة الحقيقي مع الخادم. نفّذ خطوات «إعداد Supabase» أعلاه بالترتيب، ثم جرّب: دخول المدير → إضافة أمين مخزن → دخول منه على جهاز آخر → تأكد أنه يرى الرصيد وأذون اليومين فقط وأن أي طلب REST مباشر بحسابه يُرفض للجداول المحجوبة. حتى تنفيذ هذه الخطوات سيبقى التطبيق يعمل محليًا كما هو دون أي فقد بيانات.
